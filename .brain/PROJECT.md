# XplainAI ? Project Overview

## Product Definition
**XplainAI** is an **Explainable Intelligence / AI Research Workspace**. It accepts complex user inquiries, conducts systematic multi-source research, extracts verified evidence, maps explicit factual claims, checks for contradictions and assumptions, synthesizes answers with verifiable citations, and exposes the underlying response structure through synchronized 2D/3D visual topology and interactive claim-evidence inspection ? without exposing private model chain-of-thought.

## Origin & Context
- **Hackathon Finals**: Born as an IIIT Pune hackathon finalist project.
- **Repository**: `https://github.com/mahik504/XplainAI.git`
- **Identity**: Proof of real AI engineering and explainability UX craft. Not a generic chatbot clone, not a superficial dashboard.
- **Visual & Engineering Standard**: Aligned with the Obsidian vault principles (`Preferences.md`): Swiss/editorial scientific instrument clarity, earned motion (Emil Kowalski), 3D as a functional spatial feature, strict type safety, modular provider-neutral architecture.

## Primary Surfaces & Differentiators
1. **Explainable Research Pipeline**:
   Query Analysis -> Dynamic Planning -> Parallel Multi-Source Search -> Content Normalization -> Semantic Evidence Extraction -> Claim Extraction -> Contradiction & Weakness Detection -> Synthesis with Grounded Citations.
2. **Observable Response Structure**:
   Extracts claims, supporting/contradicting evidence, inferences, assumptions, and hedges from observable artifacts and outputs.
3. **Synchronized 2D/3D Evidence Graph**:
   Interactive graph topology (Sources, Evidence, Claims, Inferences, Assumptions, Conclusions) connected via typed semantic edges (`SUPPORTS`, `CONTRADICTS`, `DERIVED_FROM`, `WEAKENS`, `DEPENDS_ON`).
4. **Bi-directional Focus & Evidence Demand**:
   Clicking any claim highlights its full supporting subgraph in the 2D/3D visualizer, surfaces the primary sources and exact snippet citations in the inspection drawer, and allows immediate "Evidence Demand" to challenge weak assertions.
5. **Traceable & Replayable Runs**:
   Every research step, tool invocation, source retrieval, and synthesis stage emits structured events with stable IDs, enabling step-by-step playback and auditability.\n
